# Development Preferences — Maxim Mitenkov (vimark.art)
# Копируй этот файл в начало каждой новой сессии с AI

## AI Collaboration
- Отвечай кратко. Меньше текста — больше кода. Показывай результат сразу.
- Всегда спрашивай перед архитектурными решениями. Не принимай их самостоятельно.
- Не over-engineer. Простейшее работающее решение лучше сложного.
- Если я даю референс (видео, картинка, сайт) — делай МАКСИМАЛЬНО похоже, не упрощай.
- Не ленись и не спеши. Лучше уточни, чем сделай "на отвали".
- Если я прошу "исправь" — исправь именно то, что указано, не ломай остальное.

## Game Development
- Управление: WASD для PC-игр. Никаких джойстиков на десктопе.
- Графика: 3D-модели, изометрия / axonometry. Не плоские 2D-спрайты.
- Персонажи и машины должны быть в 3D, видно как они выглядят.
- Звуки: реалистичные эффекты, как в референс-видео.
- Перед сдачей проверяй: нет ли черного экрана, бесконечной загрузки, неработающих кнопок.
- Если игра похожа на существующую (Brawl Stars и т.д.) — копируй механики точно.

## Web / Portfolio (vimark.art)
- Дизайн: dark & modern, минималистичный, в стиле Apple/Tobias Kwan.
- Адаптивность: обязательна. Все страницы должны работать на телефоне.
- Язык: английский для публичных страниц, описаний проектов, тегов Pinterest.
- Изображения: WebP, с lazy loading, сжатые.
- SEO: alt-тексты на английском, семантическая верстка.

### Генерация сайта
- Сайт генерируется скриптом `generate_site.py`. ВСЕ файлы в `project/*.html` и `ru/project/*.html` ПЕРЕЗАПИСЫВАЮТСЯ при каждом запуске.
- Ручные правки в `project/*.html` и `ru/project/*.html` будут потеряны. Изменять шаблоны нужно внутри `generate_site.py`.
- Перед деплоем обязателен запуск: `python generate_site.py`.
- Некоторые страницы ручные (не перезаписываются): `reviews.html`, `contact.html`, `privacy.html`, `404.html`, `thanks.html`.

### Файловая структура и данные
- Исходные изображения хранятся в папках категорий: `Book Illustrations/`, `BookCover/`, `comic/`, `Personal/`, `STRONG/`, `HERO2/`.
- `project/` и `thumbnails/` — генерируются автоматически, не редактировать вручную.
- Метаданные проектов: `projects.ini` (title, year, client, description).
- Подписи к изображениям: `captions.txt` (fallback — авто из имени файла).
- Локализация EN/RU: `locale.ini`.
- Отзывы Reedsy: `Reedsy/reviews.json`.

### Мультиязычность
- Английская версия в корне, русская — в `/ru/` с зеркальной структурой.
- При изменениях на EN-страницах проверять/дублировать в RU-версию (и наоборот).
- hreflang теги обязательны на всех основных страницах.
- Язык интерфейса переключается через футер (JS), но `lang` атрибут в `<html>` должен соответствовать версии.

### Именование изображений
- Для сортировки используются числовые префиксы: `__0001_`, `__0002_` и т.д.
- Генератор автоматически очищает префиксы для генерации подписей (captions).
- Thumbnails создаются автоматически в `thumbnails/` с тем же относительным путём, но с расширением `.webp`.

### Отзывы на страницах проектов
- Отзывы на генерируемых страницах проектов задаются в словаре `PROJECT_REVIEWS` внутри `generate_site.py`.
- Для ручных (негенерируемых) страниц отзывы вставляются напрямую в HTML в блок `<div class="project-reviews">`.
- Аватары отзывов хранятся в `thumbnails/reviews/` или `project/art/`.

### SEO
- Каждая страница должна иметь: уникальный `<title>`, `<meta name="description">`, canonical, Open Graph, Twitter Cards.
- На project-страницах обязательны: `BreadcrumbList` (Schema.org JSON-LD), `VisualArtwork` микроразметка для изображений.
- OG-image: использовать `thumbnails/` версии изображений с явными width/height.

## Integrations & APIs
- Pinterest: требуется подтверждение прав на сайт перед Rich Pins. Теги — английские, 5–7 штук.
- Google Search Console / Analytics: подтверждение через DNS у hoster.by.
- Meta API: токен привязан к Business-аккаунту, не личному Facebook.
- Telegram-боты: меню через кнопки, логика по времени суток (завтрак/обед/ужин).

## 3D & Assets
- Работаю с FBX/GLB. При необходимости оптимизируй через Houdini.
- Эмиссивные материалы — проверяй корректность в WebGL/Three.js.
- Сцены для web: отдавай целиком как GLB, если не оговорено иное.

## Code & Deployment
- GitHub + Vercel для хостинга. Проверяй наличие package.json перед деплоем.
- DNS настройки через hoster.by.
- Проверяй работоспособность после каждого деплоя.

### vimark.art
- Vercel деплоит автоматически из GitHub ветки `master`, но генератор сайта запускается локально.
- Правильный флоу: изменить исходники → `python generate_site.py` → `git add .` → `git commit` → `git push` → Vercel подхватывает.
- Проверять `git diff` перед коммитом — убедиться, что сгенерированные файлы обновились корректно.

## Debugging
- При проблемах сначала добавляй логирование, потом другие методы.
- Проверяй самое простое объяснение первым (кэш, не тот аккаунт, опечатка).
- Если я присылаю скриншот или видео — смотри внимательно, не игнорируй детали.
